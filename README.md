# RanobeSite

Закрытая площадка для чтения и публикации ранобэ, веб-новелл и рассказов. Регистрация только по приглашениям, все тексты проходят модерацию.

**Возможности**

- Каталог с поиском, фильтрами по жанрам и статусу, сортировкой и пагинацией (параметры хранятся в адресе).
- Страница произведения: главы, отзывы с оценками 1–10, комментарии, жалобы.
- Читалка: светлая, тёмная и сепия темы, 4 шрифта, размер текста, межстрочный интервал, ширина колонки, скрытие панелей, оглавление, переход клавишами ← и →, автосохранение места чтения.
- Библиотека: статусы «Читаю», «В планах», «Прочитано», «Брошено», история чтения, продолжение с сохранённого места.
- Студия автора: черновики, обложки, жанры, редактор глав на Tiptap с автосохранением, предпросмотр, отправка на модерацию, правки опубликованного без снятия текущей версии.
- Модерация: очередь, сравнение старой и новой версии, одобрение или отклонение с причиной, журнал, жалобы, скрытие произведений.
- Администрирование: приглашения, роли, переключатели «открытая регистрация» и «каталог для гостей».

**Стек:** React 19, TypeScript, Vite, Tailwind CSS 4, shadcn/ui, React Router (HashRouter), TanStack Query, Zustand, Tiptap, Supabase (PostgreSQL, Auth, Storage).

## Быстрый старт

Нужен Node.js 22.22 или новее.

```bash
npm install
cp .env.example .env.local   # затем заполните значения, см. ниже
npm run dev                  # http://localhost:5173
```

Без заполненного `.env.local` сайт не падает, а показывает экран с инструкцией по настройке.

### Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Локальный сервер разработки |
| `npm run build` | Проверка типов и production-сборка в `dist/` |
| `npm run preview` | Просмотр собранной версии |

## Настройка Supabase

### 1. Создайте проект

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте проект (бесплатного тарифа достаточно).
2. Откройте **Project Settings → API** (или **Data API**). Понадобятся:
   - **Project URL**;
   - **anon public** key или **publishable key** (`sb_publishable_…`).

   Ключ **service_role / secret** не нужен. Никогда не кладите его в `.env.local` и не передавайте в браузер. Если положить его туда по ошибке, приложение откажется запускаться.

### 2. Примените схему базы

**Вариант А — через SQL Editor (без установки инструментов).**
Откройте **SQL Editor → New query**, вставьте содержимое файла `supabase/setup.sql` и нажмите **Run**. Файл собран из всех миграций командой `npm run db:bundle`.

**Вариант Б — через Supabase CLI.**

```bash
npx supabase login
npx supabase link --project-ref <ref>
npx supabase db push
```

Миграции лежат в `supabase/migrations/` и создают:

- таблицы, индексы и ограничения;
- политики RLS для каждой таблицы;
- функции публикации и модерации;
- приватный бакет `media` для обложек и аватаров с правилами доступа;
- справочник из 20 жанров.

### 3. Настройте Auth

**Authentication → URL Configuration**

- **Site URL:** `http://localhost:5173`
- **Redirect URLs:** добавьте `http://localhost:5173/**`. После публикации сайта сюда же добавьте его адрес.

**Authentication → Sign In / Providers → Email**

- **Allow new users to sign up** оставьте **включённым**. Закрытость сайта обеспечивает база данных: триггер `handle_new_user` отклоняет регистрацию без действующего приглашения. Если выключить этот пункт, перестанут работать и приглашения.
- **Confirm email.** Встроенная почта Supabase отправляет всего несколько писем в час и годится только для проверки. Пока сайт закрыт, подтверждение можно отключить: приглашение и так подтверждает, что человек свой. Для открытой регистрации подключите свой SMTP (**Authentication → Emails → SMTP Settings**, например Resend или Brevo) и включите подтверждение.

### 4. Заполните `.env.local`

```env
VITE_SUPABASE_URL=https://<ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon или publishable key>
VITE_BASE_PATH=/
```

Перезапустите `npm run dev`.

### 5. Первый администратор

Регистрация закрыта, поэтому первое приглашение создаётся вручную. В **SQL Editor** выполните (код придумайте сами: латиница, цифры и дефисы, от 6 символов):

```sql
insert into public.invites (code, role, note)
values (upper('MOJ-SEKRETNYJ-KOD'), 'admin', 'Первый администратор');
```

Откройте `http://localhost:5173/#/register`, введите этот код и зарегистрируйтесь. Аккаунт сразу получит роль администратора. Остальные приглашения создаются в интерфейсе: **меню профиля → Администрирование → Приглашения**. Можно скопировать код или готовую ссылку.

Выдать роль существующему пользователю через SQL:

```sql
insert into public.user_roles (user_id, role)
select id, 'moderator' from public.profiles where username = 'nickname';
```

### 6. Демо-данные (по желанию)

После регистрации администратора выполните в SQL Editor файл `supabase/seed.sql`. Он добавит:

- 2 опубликованные книги с главами;
- книгу и главу, ожидающие модерации;
- черновик.

Все тексты в демо-данных оригинальные. Автором станет первый администратор. Повторный запуск ничего не дублирует.

### 7. Типы базы данных (необязательно)

`src/types/database.ts` написан вручную по миграциям. После изменения схемы его можно перегенерировать:

```bash
npx supabase gen types typescript --project-id <ref> > src/types/database.ts
```

## Как устроен доступ

Короткая версия. Подробно — в [SECURITY.md](SECURITY.md).

- **Роли:** читатель (есть у всех), модератор, администратор.
- **Закрытый режим (сейчас):** без входа не видно ничего, кроме экрана приветствия, страниц входа и регистрации. Это проверяется в базе: при прямом запросе к API гость получает пустой ответ.
- **Публикация:** любой участник создаёт произведения и главы как черновики. Читатели видят их только после одобрения модератором. Правка опубликованного проходит модерацию отдельно, и до одобрения читатели видят прежнюю версию.
- **Открытие сайта в будущем:** в **Администрировании → Доступ к сайту** есть два переключателя: «Открытая регистрация» и «Каталог для гостей». Код менять не нужно: политики RLS уже учитывают эти настройки. Перед открытием пройдите чек-лист в SECURITY.md.

## Тесты

```bash
npm test
```

- **Интерфейс** (Vitest + React Testing Library): каталог и параметры в адресе, главная, защита маршрутов, читалка и её настройки, безопасный вывод текста (XSS), ограничение частоты сохранения прогресса, отправка заявок и обработка ошибок API.
- **База данных** (`tests/db`): миграции применяются к настоящему PostgreSQL, запущенному в процессе через [PGlite](https://pglite.dev). Схемы `auth` и `storage` имитируются. Запросы выполняются от ролей `anon` и `authenticated`, как это делает Supabase. Проверяются регистрация по приглашениям, RLS, защищённые столбцы, модерация (включая повторную обработку и самоодобрение), версии глав, хранилище и демо-данные. Docker не нужен.

## Публикация (позже)

Сейчас сайт разрабатывается и проверяется локально. Workflow для GitHub Pages готов (`.github/workflows/deploy.yml`), но выключен и включается переменной репозитория `PAGES_ENABLED=true`. Порядок включения описан в комментариях внутри файла.

Учтите при выборе хостинга:

- **GitHub Pages для приватного репозитория** доступен только на платном тарифе (Pro, Team, Enterprise). Сам сайт при этом публичен для всех, закрыть его можно только на Enterprise. Данные защищены входом и RLS, но страница входа будет видна любому, у кого есть адрес.
- Если нужно закрыть даже саму страницу, подойдёт статический хостинг с ограничением доступа на входе, например **Cloudflare Pages + Cloudflare Access** (бесплатно до 50 пользователей, вход по e-mail). Сборка та же: `npm run build`, папка `dist`.
- Адрес нового сайта нужно добавить в **Site URL / Redirect URLs** Supabase, а для подпапки указать `VITE_BASE_PATH=/<имя-репозитория>/`.

В CI (`.github/workflows/ci.yml`) на каждую отправку запускаются типы, линтер, тесты и сборка.
