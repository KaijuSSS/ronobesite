- Сайт закрытый: регистрация только по приглашениям, гости не видят книги и главы.

- В будущем должна быть возможность открыть регистрацию и каталог без переписывания: сделано переключателями в `app_settings`.
- Репозиторий приватный. Публикация в интернет — позже, пока только локально.

## Что проверено

- `npm run typecheck`, `npm run lint` и `npm run build` проходят без ошибок.
- `npm test`: 83 теста.
  - 44 теста базы: RLS, приглашения, модерация, версии глав, хранилище, демо-данные.
  - 39 тестов интерфейса.
- Скриншоты интерфейса с подменой API: главная, каталог, книга, читалка в трёх темах, вход, экран гостя. Проверены ширины 1440 и 390 px. Ошибок в консоли и горизонтальной прокрутки нет.

## Не проверено (нужен настоящий проект Supabase)

- Применение `supabase/setup.sql` в облачном Supabase: триггер на `auth.users` и политики `storage.objects` проверены только на имитации схем `auth` и `storage`.
- Реальные письма Supabase Auth: подтверждение e-mail и сброс пароля (PKCE + HashRouter).
- Загрузка обложек и аватаров в Storage и подписанные ссылки.
- Сквозной сценарий в браузере: регистрация → книга → глава → модерация → чтение.

## Следующие шаги

1. Владелец создаёт проект Supabase и передаёт Project URL и anon / publishable key.
2. Применить `supabase/setup.sql`, настроить Auth по README, создать приглашение администратора, загрузить `seed.sql`.
3. Пройти сквозной сценарий вручную и исправить найденное.
4. Перегенерировать `src/types/database.ts` через Supabase CLI и сверить с ручной версией.
5. Позже выбрать хостинг с ограничением доступа (варианты в README) и включить деплой.
